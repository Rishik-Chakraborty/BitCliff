## Global Constraints

- Working dir `bitcliff/pipeline`; `uv run pytest -q` green throughout (baseline 328).
- Registered values verbatim: M = 0.03 absolute accuracy per suite; α = 0.05; 10,000 bootstrap resamples; two-sided 95% CI (percentile method, 2.5/97.5); bootstrap seed 8271 (provisional per OPEN_QUESTIONS §7), one `random.Random(8271)` stream per cell seeded as `random.Random((8271, run_id, quant_label, suite).__str__())`? NO — simpler and registered-safe: a single documented rule: `random.Random(f"8271:{run_id}:{quant_label}:{suite}")` per cell so cells are order-independent and reproducible. State this rule in FINDINGS_0B.md.
- McNemar exact, two-sided: with b = F16-right-quant-wrong, c = F16-wrong-quant-right, p = min(1, 2·min(P(X≤b), P(X≥b))) for X~Binomial(b+c, 0.5); p=1.0 when b+c=0.
- Four cell states exactly as §8 defines them (Damaged / Small real loss / Equivalent / Indeterminate). Δ = quant_acc − f16_acc; "exceeds M loss" means Δpoint < −0.03; Equivalent iff the ENTIRE CI ⊂ (−0.03, +0.03).
- Cliff per (model, suite): the highest-precision rung (ladder order Q8_0 > Q6_K > Q5_K_M > Q4_K_M > Q3_K_M > Q2_K > IQ2_M) whose cell is Damaged; also flag non-monotonic state sequences (a Damaged rung above a non-Damaged one).
- Dual rule: cells.csv carries raw per-cell p (descriptive). Headline candidates = per (model, suite) the claim "damaged from the cliff rung down"; its family = that suite's 7 ladder cells; report Holm-adjusted verdict (claim survives iff every cell it aggregates (cliff rung and below) rejects under Holm over the family).
- Truncation count per cell and both flip directions (b and c) in every row.
- Shootout trigger (§5): pairs at same label quant-vs-quant paired on identical items — Arm 1: {bartowski(from ladder run), unsloth, mradermacher_static, mradermacher_i1} × {Q4_K_M, Q3_K_M}: all 6 unordered same-label pairs per label; Arm 2: official vs bartowski at Q4_K_M, Q3_K_M. CAUTION: bartowski rungs live in run 0b-llama-8b-ladder / 0b-qwen-7b-ladder; arm files in the arm runs. Cross-run pairing is legitimate ONLY where item sets are identical — verify by comparing the two runs' items.jsonl id lists per suite; if they differ, the affected pair is reported "not pairable, item sets differ" rather than silently computed.
- Data root: `runs-cloud/pipeline/runs/` (relative to pipeline dir). Grade record fields: item_id, quant_label, suite, state (correct/partial/wrong), truncated. Accuracy = correct/n (partial counts as not-correct, matching report.py).
- FINDINGS_0B.md carries: fingerprint reference, seed disclosure, per-model cell tables (state, Δ, CI, p, b, c, truncations), cliffs, Holm verdicts, shootout trigger verdict (fires/doesn't, with the §5 consequence sentence), and the §6 note that spectacle rungs are absent from 0B by construction.

**Interfaces — Produces:**
